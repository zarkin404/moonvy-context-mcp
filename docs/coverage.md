# 覆盖率与测试约定

## 统计口径

`pnpm test:coverage` 使用 c8 收集 Node.js 的运行时覆盖数据，通过 source map 映射到 TypeScript 源码，并生成 `coverage/lcov.info`。CI 通过 OIDC 将该文件上传 Codecov。

Codecov 将未执行完整分支的行标为 partial，只用完整覆盖行计算百分比。因此，原来的本地行覆盖率 87.39% 与 Codecov 77.13% 并不矛盾：2007 行中有 1754 行被执行，但只有 1548 行完整覆盖。[Codecov 统计说明](https://docs.codecov.com/docs/about-code-coverage)

## 覆盖范围和门槛

- 覆盖 MCP 服务、stdio/HTTP 启动、配置、月维 API、转换器、素材、Tokens、预览回退和产物交付的全部运行时代码。
- c8 启用 `all`，新增但未执行的运行时模块也计入报告。
- 行、语句、函数和分支门槛均为 100%。任一指标下降，`pnpm test:coverage` 和 CI 覆盖率任务都会失败。
- 仅排除 `src/core/types.ts` 与 `src/types/config.ts`，两者只有 TypeScript 类型声明，没有运行时行为；原始运行时报告也没有统计这两份文件。不要向这些文件添加运行时代码。
- 测试脚本、测试代码和 Vue playground 不属于此 MCP 服务覆盖率的统计范围。playground 的构建和真实设计稿视觉验收另行验证。

配置位于 package.json 的 c8 字段。不要用 ignore 注释、扩大排除范围或降低门槛来绕过缺失测试。新增分支应补充能够验证预期行为的测试。[c8 配置说明](https://github.com/bcoe/c8#checking-for-full-source-coverage-using---all)

## 主要验证行为

| 范围       | 验证内容                                                                           |
| ---------- | ---------------------------------------------------------------------------------- |
| 配置和 CLI | 参数优先级、外部 env 文件、工作目录、有效值和启动失败退出码                        |
| HTTP       | 真实 SDK 初始化、工具调用、方法限制、端口冲突、通用错误和响应已发送后的错误        |
| 月维 API   | 鉴权隔离、响应包装、压缩解码、资源白名单、流式大小限制和素材元数据补充             |
| 转换器     | 文字分段和链接、布局、渐变、描边、阴影、模糊、变换、资源去重、单位缩放和复杂度限制 |
| MCP 和资源 | 多画板选择、各类 MIME、错误脱敏、目录穿越、符号链接逃逸和文件交付                  |
| 预览回退   | 已有素材优先、实例边界、裁切像素、越界拒绝和输入不被修改                           |

覆盖率是路径执行指标，不代表所有设计稿都能正确转换，也不代表视觉还原度为 100%。真实设计稿仍通过 `pnpm test:live` 对照预览验收。

## 2026-10-14 验证记录

61 项测试通过，运行时源码的行、语句、函数和分支覆盖率均为 100%。测试同时发现并修复了 HTTP 端口冲突被误报为启动成功的问题。

既有真实月维样例的 CSS、Tailwind 3/4 截图结果保持一致；Vue 页面与 Tailwind 参考页没有像素差异。与原设计预览的差异仍为此前的 3.32%（通道误差大于 24 的像素占比），未因覆盖率修改而增加。
